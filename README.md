# 원격지원 — 직원별 이름 설정 버전 0.7

**직원이 코드 발급 → 학생이 웹사이트에서 코드 입력 → EXE 다운로드·실행 → 학생이 승인 → 직원이 상대 PC 조작** 방식입니다.

v0.7은 처음 입력한 **이름과 사이트 소개 문구**를 프로그램 제목, 안내 복사 링크의 사이트, 학생용 프로그램에 반영합니다. `민주쌤`은 `민주쌤 원격지원`, `아진쌤`은 `아진쌤 원격지원`으로 표시됩니다. **UPDATE-PERSONAL-NAME.md**에 적용 순서와 이름 없는 기본 주소의 설정 방법이 있습니다.

접속 웹사이트, 코드가 포함된 학생용 EXE를 생성하는 다운로드 기능, 윈도우 클라이언트 소스, 무료 Windows 빌드 설정, 중계서버 설치 파일이 포함되어 있습니다. **미리 빌드된 EXE와 운영 중인 중계서버는 포함되어 있지 않습니다.** 중계서버 테스트 28개는 통과했지만 윈도우에서의 컴파일, 화면 캡처, 입력 제어, 두 PC 간 실제 연결은 아직 검증하지 못했습니다. 먼저 테스트용 PC에서 실행하세요.

SSL/TLS 연결 오류가 있었다면 먼저 **TLS-FIX.md**의 적용 순서를 따르세요. v0.3 수정 당시 실제 운영 서버의 HTTPS 상태 확인과 TLS 1.2 WebSocket 코드 발급에 성공했습니다. Windows 클라이언트 자체의 수정본 실행은 여전히 실기 확인이 필요합니다.

v0.7은 **직원별 이름과 소개 설정**을 지원합니다. 처음 한 번 자기 사이트 주소와 이름, 소개를 저장하면 다음부터 자동 적용됩니다. 접속 코드는 **숫자 6자리**입니다. 배포 방법은 **DISTRIBUTION.md**를 참고하세요. 현재 버전 적용 방법은 **UPDATE-PERSONAL-NAME.md**를 참고하세요.

## 사용 순서

1. 무료 서버·주소 설치와 Windows EXE 빌드는 `relay/RENDER-FREE.md`를 따릅니다.
2. **직원 PC**에서 `client/Start.cmd`를 실행합니다. 최초 실행 시 EXE를 만들며, GitHub Actions로 만든 템플릿 EXE를 그대로 실행해도 됩니다.
3. 프로그램 첫 실행에서 자기 HTTPS 사이트 주소와 이름·소개를 한 번 저장합니다. 정현쌤 기존 주소는 `https://jh-remote-support.onrender.com`입니다. 다음부터 바로 **코드 발급**을 누릅니다.
4. **안내 복사**를 눌러 접속 웹주소와 코드를 학생에게 전달합니다.
5. **학생**은 웹주소에 접속하고 코드를 입력한 뒤 **지원 프로그램 다운로드**를 누릅니다.
6. 내려받은 **단일 EXE 파일**을 실행합니다. 프로그램에는 코드와 서버 주소가 포함되어 있으며, 별도로 입력할 필요가 없습니다.
7. 실행 후 뜨는 승인 창에서 학생이 허용하면 직원 화면에 학생 PC가 열립니다.
8. 어느 쪽에서든 **즉시 종료**를 누르면 종료됩니다. **프로그램에 표시된 종료 단축키**도 사용할 수 있습니다.

현재 패키지에는 미리 컴파일된 EXE가 없으므로 템플릿을 빌드해 `relay/downloads/JHRemoteSupport.exe`에 넣어야 다운로드가 동작합니다. 없는 EXE를 내려받는 척하지 않고 준비 중 안내를 반환합니다. 실제 웹사이트 주소는 서버 배포 후 발급됩니다.

대기 코드는 10분 뒤 만료됩니다. 승인 요청은 60초 뒤 취소됩니다. 연결이 종료되면 기존 코드는 무효화되며 새 코드를 발급해야 합니다. 세션은 코드 발급 후 최대 2시간으로 제한됩니다. 상대방이 연결 승인 전에 거절한 경우 지원자 코드는 남은 유효시간 동안 다시 사용할 수 있습니다.

## 포함 기능과 범위

| 항목 | 현재 상태 |
| --- | --- |
| 지원자가 코드 발급, 학생이 웹사이트에서 코드 입력 | 구현 |
| 단일 EXE 다운로드와 코드 자동 전달 | 서버 구현·테스트 통과, Windows EXE 실행 검증 대기 |
| 지원받는 사람의 연결 승인·거절 | 구현 |
| 기본 모니터 화면 공유 | 구현, 윈도우 검증 필요 |
| 마우스 이동·클릭·드래그·휠 | 구현, 윈도우 검증 필요 |
| 일반 키보드 입력 | 구현, 윈도우 검증 필요 |
| 종료 버튼·종료 단축키 | 구현, 윈도우 검증 필요 |
| 승인 전 화면·입력 차단, 종료 후 코드 폐기 | 서버 테스트 통과 |
| 파일 전송·멀티 모니터 선택·무인 접속 | 미구현 |
| UAC 권한 요청·잠금 화면·Ctrl+Alt+Delete | 지원하지 않음 |

주요 대상은 **Windows 10/11 + .NET Framework 4.8**입니다. 화면은 가로·세로 최대 1280px, JPEG 품질 55, 약 6fps로 전송합니다. 문서와 웹사이트를 안내하는 초기 버전이며 영상이나 게임 원격조작용은 아닙니다. 한글 입력과 단축키는 양쪽 키보드 배열 및 지원받는 PC의 IME 상태에 영향을 받습니다. 일부 Windows 시스템 단축키는 지원자 PC에서 먼저 처리될 수 있습니다.

## 윈도우 실사용 검증

아직 아래 결과가 확인되지 않았습니다. 테스트 후 운영 여부를 결정해야 합니다.

- `Start.cmd`로 컴파일 및 프로그램 창 실행
- 코드 발급 후 다른 PC가 코드 입력, 거절 및 재요청
- 승인 이전 화면이 전송되지 않음, 승인 후 화면 표시
- 메모장에 영어·한글 입력, Shift·Ctrl 조합, 클릭·드래그·휠
- 지원자 창에서 다른 창으로 이동할 때 원격 PC에 눌린 키가 남지 않음
- 종료 버튼, 프로그램에 표시된 종료 단축키, 네트워크 끊김 이후 공유와 입력 중단
- 종료 후 이전 코드로 재접속 불가
- 서로 다른 인터넷 회선에서 WSS 서버 연결

컴파일 실패 메시지나 실제 실행 오류가 있으면 메시지 내용으로 수정할 수 있습니다. 인터넷 배포와 윈도우 실기 검증이 필요합니다. 초기 템플릿은 코드 서명되지 않았으며 다운로드 시 EXE 뒤에 설정을 붙입니다. Windows 게시자 확인 경고가 나타날 수 있습니다. 서명된 배포를 도입할 때는 이 동적 파일 형식도 함께 변경해야 합니다. 보안 기능을 끄도록 구성하지 않았습니다.

## 연결과 데이터

외부 연결은 인증서 검증을 포함한 **WSS**만 허용합니다. `ws://127.0.0.1:8765/support`는 개발자의 같은 PC 테스트에만 허용합니다. PC 간 포트포워딩은 필요하지 않지만 중계서버를 인터넷에 운영해야 합니다.

화면과 입력은 중계서버를 거칩니다. TLS는 PC↔서버 구간을 암호화하며 **종단간 암호화는 구현하지 않았습니다.** 따라서 서버 운영자는 중계 내용을 볼 수 있는 위치에 있습니다. 코드에 화면·입력 저장 기능은 없고 세션은 서버 메모리에만 유지됩니다. 지원자 표시 이름은 직접 입력한 값이며 신원 인증 기능은 아닙니다. 코드는 직접 전달한 사람과 함께 사용해야 합니다.

## 서버 검증 결과

`python -m unittest discover -s tests -v` — **28개 통과**.

코드 발급 주체, 승인, 승인 전 차단, 종료·코드 폐기, 세션 격리, HTTP 페이지, 코드별 EXE 다운로드 응답 및 설정 삽입을 로컬 HTTP/WebSocket으로 확인했습니다. 다운로드 테스트의 PE 바이트는 테스트용 모형이며 실행 가능한 EXE를 검증한 결과가 아닙니다. 이 결과가 윈도우 화면 캡처·입력 제어 또는 인터넷 운영 검증을 대신하지는 않습니다.
