# 중계서버 연결

서로 다른 인터넷의 두 PC가 연결하려면 인터넷에서 접근할 수 있는 HTTPS/WSS 서버가 필요합니다. 이 파일은 설치 방법이며 서버가 이미 운영되고 있다는 뜻은 아닙니다.

## 공용 서버 설치

필요한 것: Docker Compose를 사용할 수 있는 리눅스 서버, 그 서버를 가리키는 도메인, 외부에서 접근 가능한 TCP 80·443 포트. 도메인·서버 비용은 해당 공급자에 따라 달라집니다. 이 프로젝트에서 서버나 도메인을 구입하지 않았습니다.

1. 서버에 `relay` 폴더를 복사합니다.
2. `.env.example`을 `.env`로 복사하고 `SUPPORT_DOMAIN`을 본인 서버를 가리키는 실제 도메인으로 수정합니다.
3. `relay` 폴더에서 실행합니다.

```sh
docker compose up -d --build
docker compose logs --tail=50
```

4. DNS와 방화벽이 맞으면 Caddy가 HTTPS 인증서를 발급합니다.
5. 두 윈도우 프로그램에 `wss://설정한도메인/support`를 입력합니다.

relay 컨테이너의 8765 포트는 외부에 공개하지 않습니다. 외부 접속은 Caddy의 443 포트로만 전달합니다. 현재 시도 횟수 제한은 서버가 보는 연결 IP 기준이며, 이 프록시 구성에서는 합산된 요청에 적용됩니다. 대기 코드 생성 및 코드 입력은 각각 분당 10회로 제한되어 있으므로 다수 동시 상담 운영에는 실제 이용량에 맞춘 프록시 IP 처리와 인증 기능 보강이 필요합니다.

중단:

```sh
docker compose down
```

서버 중단 시 진행 중인 원격지원도 종료됩니다.

## 같은 PC에서 서버 로컬 테스트

Python 3.12 환경에서:

```sh
python -m pip install -r requirements.txt
python server.py
```

윈도우 프로그램 주소는 `ws://127.0.0.1:8765/support`입니다. 기본 서버는 루프백으로만 대기합니다. 이 주소로 다른 사람의 PC가 인터넷에서 접속할 수는 없습니다. 로컬 테스트 후 외부 접속에는 위 WSS 설치가 필요합니다.

## 운영 범위

TLS 배포·도메인 발급·윈도우 두 PC 실기 검증은 이 작업 환경에서 수행되지 않았습니다. 서버는 파일에 화면이나 입력을 기록하지 않지만 중계 내용을 처리합니다. 민감한 운영 환경에 쓰기 전 코드 검토, 인증·권한 체계, 코드 서명 및 부하 검증이 필요합니다.
